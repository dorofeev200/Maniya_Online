прочие FP, зафиксированные в отчётах. Критерий MANIYA BUG (все три одновременно):
правильный playable-кандидат ЕСТЬ в accessible фиде + Нормалайзер выбирает неправильного
+ выбор чинится безопасным правилом. Иначе — UPSTREAM/CATALOG LIMITATION, или правильный
результат = EMPTY (feed только из реакций/обзоров/сиквелов).

## 1. Live-прогон (18.08, актуальный код, реальный Rutube API)

Прогонялся реальный pipeline: `RutubeProvider.videos()` → `search` (RU+EN, yearful→yearless)
→ `RutubeNormalizer` scored ranking → `playOptions` → m3u8. Плюс сырая выдача со счётами
и deep-check по ключевым запросам.

**Важный факт:** живая выдача Rutube изменилась с 16.08 (даты аудита). Полные копии
появились почти по всем проверяемым фильмам — остаточные FP-кандидаты аудита (Path of Neo,
реакции, ambient, лекции, «TEAM SPIDER MAN DUNE», «смотрим вместе», Гурджиев/хор) в текущей
выдаче либо отсечены скоррингом, либо ушли из топа. Каждая фиксированная в отчётах
FIX-001 live-таблица строка теперь либо уже исправлена, либо закрыта как data-лимит.

## 3. Пограничный кейс: «Матрица» БЕЗ year (year=0)

Проверен честно: если query.year=0 (Lampa не прислал год — на практике шлёт всегда,
addMovieParams), сиквел «Воскрешение (2021)» имеет s=6 (точный титл-лидер/год не штрафуется,
т.к. year=0) и выходит в топ по длительности (8878s > 8226s оригинала). Это НЕ воспроизводится
в реальной схеме: клиент всегда шлёт `year` (из release_date), год в титле у сиквела получает
−3, оригинал побеждает. Гипотетический риск без реального триггера — не фиксируется (не Maniya bug).
