## 1. Что делает SKAZ (3 слоя, все сверены)

### 1.1 Живая lite-сессия кластера → набор источников меняется сам (D3-ядро)
- `createSource()` (3246) → `lite/events?life=true` (X-Kit-AesGcm, таймаут 15с) → `{memkey, life:true}`.
- `lifeSource()` (3173): поллинг `lifeevents?memkey=…` **каждую 1с** до `ready:true` или 15 тиков
  (life_wait_times > 15 → ранний resolve). Каждый ответ `json.online[]` **живо переписывает**
  `sources[name]={url,name,show}`, `filter_sources`, `filter.set('sort')` (3203-3219) — источники
  **появляются/пропадают/меняют show прямо на карточке** во время загрузки, без пересоздания экрана.
- `uiLoadingProgress(json, times)` (1325): found = count(show), бар = ready?100:min(95, times/15*100).
- WATCHDOG (424: 24с / 425: 40с первый): `uiWatch` (1344) — зависший балансер → `doesNotAnswer`.

### 1.2 Фоновый probe источников (D8) + live-подсветка чипов (probeMark)
- После отрисовки `probeBackground()` (1926) через PROBE_DELAY=1.5с → `probeSources(all)` (1976):
  **один проход** по реестру, PROBE_LIMIT=26, PROBE_PARALLEL=2 воркера, PROBE_BUDGET=45с,
  PROBE_TIMEOUT=7с на URL → вердикт ok/empty/skip → `probeSave(name,state,count)` (1892) в кэш
  `skaz_probe` (TTL: ok 6ч / empty 30м — 1885).
- `probeMark(name,state,count)` (1951): **пока раскрыт любой drop** — источник, которого НЕТ в ряду,
  но probe дал 'ok', **чип ДОБАВЛЯЕТСЯ В ЖИВУЮ** (1956-1961) с бейджем качества + зелёной ●;
  'empty' → `skaz-chip--empty` (затемнение, точка убирается); rch/accsdb → skip.

### 1.3 Авто-переключение мёртвого активного (D4)
- `doesNotAnswer(er)` (4496): modern-note «источник пуст/не отвечает» + **таймер-тикание 6с**
  (10с при accsdb), гейт `Lampa.Storage.get('skaz_auto_switch', true)` (4505);
  затем `nextSource()` (2364) — ранжирование `sourceState`: 'ok'(жизнь по probe) > knownQuality >
  show — и `switchSource` БЕЗ выхода из карточки.

## 2. Что сейчас у нас (проверено по коду)

- **Контракт single-shot**: `/sources/card` (кард-модель show/ghost/index) — ОДИН запрос при входе;
  сервер кэширует availability 5 мин (hide 60с). После входа набор СТАТИЧЕН.
- `probeSources(ordered)` (937): **один проход ≤6 кандидатов** при входе, live Range-проба плей-ссылок
  (8с, AbortController) → 'confirmed'/'dead'(→ ghost, `uiDeadSources[k]=true`)/'unverified'.
  Активный = первый confirmed, иначе первый unverified, иначе первый кандидат. Повторных циклов НЕТ.
- `uiRefreshGhost()` (929): точечная перестройка ТОЛЬКО раскрытого `.z01-drop`, только при
  `ui.open==='source'` (сделано в T047 против «моргания»). Поздние вердикты probe подхватываются им.
- `changeSource(key)` (1606): ручное переключение из тулбара → `loadVideos()`. Авто-переключения нет;
  ошибка воспроизведения → note + ручная смена источника.
- `maniya_online_source`: **глобальный** «последний источник» по фильмам (не per-movie).
- Тонкий клиент `ThinSkaz` (T052/T054): девайс сам лайт-резолвит живую `online[]` кластера для
  skaz-thin-модулей (sessionManager/nws) — НО только для thin-списка, не для нативного реестра.

## 3. Почему ПОЛНЫЙ клон невозможен с нашего VPS (честное ограничение)

1. **`online[]` кластера** вычисляется кластером ДЛЯ ДЕВАЙСА (по его IP/сессии). Наш VPS-минт для
   самого себя — single-shot и «дроzhat» (T051): повторить lifeevents-поллинг, чтобы источники
   **появлялись у кластера и приходили к нам**, серверно мы не можем.
2. **Новые источники вне нашего реестра/кард-модели** мы физически не увидим — «появятся источники,
   которых никогда не было» — это EXCLUSIVE-фича живой сессии, недоступна нам по контракту.
3. Серверный кэш availability (5 мин) в любом случае делает флаги «живости» устаревшими против
   реального здоровья стрима — но для этого и нужен **клиентский** direct-probe (как у SKAZ).

## 4. Достижимо без риска (РЕКОМЕНДАЦИЯ) — 4 куска, всё client-only

Всё в `public/maniya-online.js`, всё под гейтом `Z01_UI_OK` (legacy и vm-тесты не задеваем),
сервер не меняем, PROD не трогаем, деплой только staging (95.85.241.121).

### E1 — периодический фоновый RE-probe известных источников (наш аналог probeBackground+probeSources+probeMark)
- После успешной `draw()`/`loadVideos()` заводим ОДИН таймер, тик **~25с** (SKAZ делает 1.5с после
  отрисовки и всё; нам по жизненному циклу карточки удобнее периодический). На каждом тике:
  - ре-проб НЕ всех подряд, а прицельно: `uiDeadSources`/ghost (вдруг ожили) + текущий активный
    (вдруг умер); параллель 2, таймаут на URL 7с, бюджет тика ~20-30с;
  - проба = та же live Range-проба что в `probeSources` (bytes=0-1023, 8с).
- Вердикт изменился → `sources[k].show/ghost` флип → `updateFilter()` + `uiRefreshGhost()` (уже есть,
  перестраивает открытый drop) → **чип появляется/гаснет + ●/затемнение в раскрытом drop без выхода
  из карточки**; бейдж качества чипа — из тех же данных что в `sourceLabel`.
- Кэш вердиктов: **in-memory Map** (не Storage): ok → TTL ~6ч (не трогаем часто), empty → TTL ~25-30с
  (чтобы оживание ловилось быстро). Сметается при смене карточки/`reset()`.
- Гигиена таймера — урок STABILITY-004 (orphan-promise крашнул PROD): один глобальный таймер,
  `clearInterval` в `reset()`/смене карточки/unload, каждый проба в `.catch(){}`, бюджет через deadline.

### E2 — авто-переключение мёртвого активного (наш аналог doesNotAnswer)
- Вешаемся в существующий обработчик ошибки воспроизведения (там, где сейчас note): «источник пуст/
  не отвечает» → modern-note + тикание 6с, гейт-storage `maniya_auto_switch` (default true) →
  `changeSource(nextSource)`, где `nextSource` ранжирует: 'ok' по live-probe > knownQuality >
  серверный порядок. Ручной выбор юзера всегда побеждает.
- Анти-thrash: максимум **2 авто-переключения на карточку**, затем только ручной выбор.

### E3 — thin-путь (единственный способ увидеть по-настоящему НОВЫЕ источники)
- Для skaz-thin-модулей девайс УЖЕ резолвит живую `online[]` (thinFlow). НЕ сопрягаем E1 с thin;
  lifeevents-поллинг 1с с девайса (как SKAZ) — отдельный W2b: цена (1 запрос/с + X-Kit-заголовок) и
  семантика TTL на нашей кард-модели требуют отдельного дизайна. Рекомендуем ИЗ СКОУПА сейчас.

### E4 — честные границы «живости» (что увидим и чего нет)
- УВИДИМ: умер → затух/уехал в «Ещё N» в течение ~30с без выхода из карточки; ожил (был ghost) →
  чип вернулся с ●; активный умер → note + таймер + авто-switch. Всё — в открытом drop и бейдже.
- НЕ УВИДИМ: появления источника, которого нет в реестре/кард-модели (нужна живая сессия кластера);
  мгновенных (1с) смен набора между тиками.

## 5. «Ничего не поломать» — контроль рисков

- **Client-only + Z01-гейт**: legacy-путь и vm-песочницы (Z01_UI_OK=false) вообще не выполняют новые
  ветки; контракт-тесты не трогают рендер. Никаких изменений сервера → семантика availability-кэша
  и кард-модели не меняется.
- **Стоимость**: 2 параллельных Range-пробы × 7с максимум раз в ~25с, ТОЛЬКО пока открыта карточка
  сериала/фильма и тик запущен. Пауза пробы, когда активен плеер / document hidden — не мешаем
  воспроизведению.
- **Таймеры/анкеты**: один глобальный interval, чистка в reset/смене карточки, `.catch` везде
  (STABILITY-004). Бюджет тика через deadline, а не «долго висим».
- **Rollback без пересборки**: client kill-switch `maniya_live_probe` (default on) — на девайсе
  выключили → старое поведение целиком; бандл не откатываем.
- **A/B только staging**: девайс + ноут против SKAZ (эталон = та самая живая подсветка). Приём — как
  T058/W1: чип появился/исчез и ● горит без выхода из карточки. PROD 0 обращений (проверка логов).
