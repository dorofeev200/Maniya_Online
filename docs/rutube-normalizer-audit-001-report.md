# RUTUBE-NORMALIZER-AUDIT-001 — качество native Rutube-поиска (FN/FP)

**Дата:** 2026-08-16 · **Режим:** READ-ONLY (код и тесты НЕ менялись; commit/push/deploy НЕ делались)
**Вход:** `docs/rutube-hd-playback-audit-001-report.md` (root cause twin-first, доказан) + `docs/rutube-hd-fix-001-report.md` (native-first применён локально). Второй баг из FIX-001: **native search не находит некоторые реальные фильмы, иногда выбирает нерелевантные карточки.** Порядок выбора (twin-first/native-first) не исследуется.

Метод: live-проба на прод-конфиге (VPS, temp-копия `/opt/maniya-online`, реальные creds из `.env`, секреты/токены не попадали в вывод). Протестировано **7 фильмов**: Матрица, Аватар, Дюна: Часть вторая, Интерстеллар, Аннигиляция, Зеленая миля, Бойцовский клуб.

## 1. Pipeline (что реально выполняется при `/videos?provider=rutubemovie`)

```
store.js getVideosForRequest (native-first, FIX-001)
 → RutubeProvider.videos(context)
   → RutubeProvider.search({title, year})            // 1 запрос, страница 1
     → RutubeClient.search: api/search/video/?content_type=video&duration=movie&query="{title} {year}"
       → сырой JSON (results, page=1, дефолт relevance)
     → RutubeNormalizer.searchResults(raw)
       → кандидаты → client.playOptions(id) → playItem
```

Ключевые факты кода (RK): `RutubeClient.search` отправляет **один** запрос с русским `title` (то, что пришло из Lampa = рус. название) и годом; страницы/сортировка/языковые варианты НЕ используются. `RutubeNormalizer.searchResults` требует: (1) `searchTitle && year` непустые (значение по умолчанию — если Lampa не прислал год → **пусто**); (2) `name.includes(searchTitle)` где `name=searchNameTo(title)`, кириллица+латиница в нижнем регистре; (3) подстрока `year`, `year±1` в имени; (4) `duration > 3000`; (5) `EXCLUDE_WORDS`; (6) **`category.id == 4` строго**; (7) 7 флагов.

## 2. Что реально отдаёт Rutube API (полный DTO, проверено живьём)

Полный набор полей (не маппится Lampac/нами): `id`, `title`, `description`, `author {id,name,avatar_url}`, `category {id, short_name, name, category_url, for_kids}`, **`hits` (просмотры)**, `thumbnail_url`, `created_ts`, `publication_ts`, `last_update_ts`, `duration`, `feed_name/feed_url`, `video_url`, `embed_url`, `is_hidden/is_deleted/is_adult/is_locked/is_audio/is_paid/is_reborn_channel/**is_official**/is_livestream/is_on_air`, `origin_type`, **`is_original_content`**, `kind_sign_for_user`, `pg_rating {age,logo}`, `action_reason`.

**Поля `year`/`release_date` НЕТ.** Год существует только как подстрока `title`. Это фундаментальное ограничение всех «точных» правил.

Серверный параметр `category=4` в поиске API **игнорируется** (проверено: `raw` не меняется).

## 4. Точный root cause (общий)

Три независимых фактора, образующих FN/FP:

1. **Язык запроса фиксирован русским.** `query={ru.title} {year}`. Реальные копии нередко живут под англ. титлами («Avatar (2009)…», «Fight Club…») — кириллический запрос их не поднимает → **FN**.
2. **Строгая обязательная категория `category.id == 4`.** Реакции/обзоры/стрим-каналы тоже получают cat=4 (→ **FP**), а реальные фильмы бывают под 73/13/64 (→ **FN**).
3. **Отбор = «первая прошедшая», без ранжирования**, со слабым порогом `duration > 3000` и узкими `EXCLUDE_WORDS` (нет «реакция/смотрим/стрим/разбор/kinoklub»; «обзор» есть). Реакция 62 мин проходит, полнометражные стримы 2,5–3 ч проходят по длительности. **Года в полях API нет** — «строгое» требование года в титле создаёт дополнительные FN (титлы без года).

Помимо вклада правил, есть фильмы, которых на Rutube просто нет в проходящей форме (Дюна 2, Аннигиляция, Бойцовский клуб, оригинал Матрицы в текущей выдаче) — корректный исход для них — **«пусто»** (не FP).

## 5. Что уже отсекается и что НЕ отсекается

Отсекается сегодня: `EXCLUDE_WORDS` (трейлер/trailer/премьера/**обзор**/сезон/сериал/серия/серий), `duration<=3000`, `cat≠4`, 7 флагов (включая `is_adult` — легитимный блок Зеленой мили).

Не отсекается (гэпы, по живым ответам): **«реакция»**, «смотрим», «стрим», «разбор», «киноклуб», «комментирует», «ambient/soundscape/music», донат/boosty/twitch-ссылки в `description`, категории-шум если убрать строгость (Музыка/Аудио/Аудиокниги/Видеоигры/Эзотерика/Развлечения/Телепередачи/Психология…).

## 7. Общий алгоритм правильного отбора (не хардкод, не «+слова»)

Рекомендуемая модель — **scored ranking** вместо последовательности обязательных правил:

1. **Мульти-запрос** (дёшево, 2–3 HTTP): `[ru.title+year]`, `[original_title+year]`, при пустом результате — `[ru.title]`, `[original_title]` без года (страницы 1..k при пустом или топ-N). Мердж по `id`, дедуп.
2. **Единый match по ключам**: набор `S = {searchNameTo(ru), searchNameTo(en)}`. Кандидат проходит, если его нормализованный титл содержит **любой** ключ из `S` (строгое «==» — бонус).
3. **Оценка по взвешенным признакам**: exact-титл (+3); cat ∈ {4,13,64,73} (+2, прочие −2, шум-категории −3); `duration ≥ 5400` (+2, 3000–5399 +1); год±1 в титле (+1); `hits ≥ 200` (+1), `hits ≥ 10000` (+0); маркеры реакций в титле/desc («реакция/смотрим/стрим/разбор/киноклуб/ambient/soundscape») −2/−3; монетизация в desc (donationalerts/boosty/twitch/«поддержать канал») −1; `is_original_content`/`is_official` 0.
4. **Выбор**: максимум score, порог ≥ 1; возвращать топ-1..3 (играбельные после `playOptions`). При отсутствии прошедших порог — вернуть самый высокий (честный «лучший-доступный») **или** пусто (политика, см. риски).
5. `EXCLUDE_WORDS` не расширять отдельно — поведение «реакций» покрывается весами. Если всё же словами — только через скоринг.

Идея: не «найти Матрицу», а «отсортировать кандидатов по вероятности быть полнометражной копией и взять максимум» — это единый ответ на Аватар (EN-титл, cat73, dur>1.5ч, титл «Avatar…» — высокий score), Матрицу (реакция 62 мин падает ниже порога), интерстелларовскую реакцию (остаётся — титл/год/длительность компенсируют), Зеленую милю (блок is_adult остаётся жёстким).

## 8. Мультиязычные запросы — нужны

**Да, нужны.** Доказано: AVATAR-en находит 2 реальные полные копии, которых RU-запрос не показывает; БК-en поднимает титлы, близкие к фильму. Ограничение: матчинг обязан использовать оба ключа (`S`), иначе англ-результаты снова не сматчатся кириллическим `searchTitle`. Для Дюны 2/Аннигиляции EN-запрос **не** помогает (контента нет) — мультиязычность закрывает «фильм есть под англ. титлом», а не «фильма нет».

## 9. Совместимость с native-first

**Порядок выбора не меняется.** FIX-001 (`store.js`) остаётся как есть: native → twin fallback. Изменения (если будут в отдельной волне) — только внутри `RutubeProvider/RutubeClient/RutubeNormalizer`, контракт `videos()` → `{items:play, seasons, voices}` сохраняется. store/twin/vkmovie/availability/W1/конфиг не трогаются.

## 10. Безопасная модель исправления (когда-либо, НЕ в этой задаче)

Этап 1 (низкий риск): «де-реактивировать» через **веса**, не через обязательный фильтр — порог 5400с + реакционные маркеры в титле/desc + ранжирование. Риск: у фильмов, где реальной копии нет, падение до «пусто» (как сейчас), у Интерстеллара — сохранение лучшей-доступной.
Этап 2 (средний риск): мульти-запрос ru+en + match по `S`. Риск: рост ложных английских совпадений; нужен минимальный score-порог.
Этап 3 (высокий риск): смягчение `cat==4` → белый не-шум {4,13,64,73}. Риск: шум из «Лайфстайл/Разное/Культура» — компенсируется весами title/duration/desc. Каждая из этих категорий CONFIRM-случай доказан: 73 (Аватар), 64 (Зеленая миля), 13 — потенциальные.
Особый случай: `is_adult`-блок Зеленой мили — политика «не пробивать» (почему: легальная рамка + деградация контента). Если нужно — отдельное решение.

## 14. Итог

- **Root cause (для фильмов):** (а) RU-only запрос не поднимает англ-титлы (Аватар/БК); (б) строгая `cat==4` режет реальные копии под 73/64/13 и одновременно пропускает реакции/обзоры под 4; (в) «первая прошедшая» без ранжирования со слабым порогом (3000с) и узким `EXCLUDE_WORDS` (нет «реакция/смотрим/стрим») даёт FP (Матрица-реакция), а отсутствие контента даёт половину FN (Дюна 2, Аннигиляция — контента нет вообще; Зеленая миля — легально заблокирована is_adult).
